- Empty + 온도 같은 데이터 오류도 일단 표시 (검수원이 보고 판단)

==================================================
  M2.4 — 온도 자연어 검색 + 정규화
==================================================

✅ 문제: "리퍼 영하 18도 몇개야" → AI 답 못함
✅ 원인:
   - EDI 온도 형식 "-018" (앞 0 채워짐) → 숫자 비교 안 됨
   - nlSearch에 온도 파싱 로직 없음 → 18을 컨번호로 인식

✅ 해결 1: EDI 파싱 시 온도 정규화
   "-018" → "-18"
   "-02.5" → "-2.5"
   "000" → "0"

✅ 해결 2: 자연어 온도 파싱 추가
   "영하 18도", "-18도", "마이너스 18도" → temp = -18
   "영상 5도", "+5도" → temp = 5
   "0도" → temp = 0
   "리퍼 18도" → temp = 18 (리퍼 컨텍스트면 영상)

✅ 해결 3: 온도 매칭 (0.5도 이내 일치)
   질의 -18 vs 데이터 -18.0, -17.8, -18.2 모두 매칭

【테스트 케이스】
"리퍼 영하 18도 몇개야"  → 리퍼 영하 18도 11대
"-18도 몇개"              → 리퍼 영하 18도 11대 (자동 리퍼)
"리퍼 -25도 몇대"          → 리퍼 영하 25도 10대
"리퍼 영하 2.5도"          → 리퍼 영하 2.5도 16대 (소수점)
"리퍼 0도"                  → 리퍼 0도 2대

==================================================
  M2.5 — 트윈 짝꿍 베이 자동 분석 (★EDI 기반★)
==================================================

✅ 핵심 알고리즘 (사용자 알려주신 패턴):
   1. EDI에 있는 모든 베이 분석
   2. 짝수 베이(40ft 슬롯)가 있으면 → 양옆 홀수가 짝꿍
   3. 짝수 베이가 없으면 (통로) → 양옆 홀수는 단독

   예시: 베이 [01, 02, 03, 05, 06, 07]
   - 02 있음 → 01-03 짝꿍
   - 04 없음 (통로) → 03 다음 짝꿍 시작점
   - 06 있음 → 05-07 짝꿍

   ATPR 2622E 검증 결과:
   - 001 ↔ 003 (002 슬롯)
   - 005 ↔ 007 (006 슬롯)
   - 009 ↔ 011 (010 슬롯)
   - 013 ↔ 015 (014 슬롯)
   - 019 ↔ 021 (020 슬롯)
   - 023 ↔ 025 (024 슬롯)
   - 028: 단독 (FR 4개)

✅ 동적 재매칭:
   - 검수 완료된 컨은 짝 후보에서 자동 제외
   - 한 짝이 다른 컨과 매칭되면, 남은 짝꿍이 다음 컨과 자동 매칭
   
   시나리오:
   1. 1234 검색 → 8765 추천 (잘못)
   2. 검수원 수정: 5678로 변경 → 완료
   3. 다음 4321 검색 → 8765 자동 추천 (1234가 5678로 페어링되어 8765는 미페어링 상태)

✅ 단독 베이:
   - 통로 사이의 베이 (양쪽 짝수 슬롯 모두 없음)
   - 짝꿍 추천 X
   - 검수원이 직접 매칭

【테스트 방법】
1. 트윈 모드 진입
2. 003 베이의 컨 입력 → 001 베이 컨 자동 추천 (002가 슬롯)
3. 다른 컨으로 변경 시 동적 재매칭 확인

==================================================
  M2.6 — 선박 라이브러리 (★학습된 선박 영구 보관★)
==================================================

✅ 핵심: EDI 분석한 선박 정보 = 영구 자산
   - 선박은 같으니 베이 페어링/구조 = 항상 동일
   - 한 번 분석하면 다음 항차에서 즉시 활용
   - 5명 검수원 모두 자동 공유

✅ 자동 동작:
   1. EDI 업로드 → TDT 세그먼트에서 IMO 추출
   2. ships/{IMO} 조회
      ├ 있음 → "📚 학습된 선박 N개 항차" 표시
      └ 없음 → "🆕 새 선박" 표시
   3. 베이 분석 (페어링, 단독, 슬롯)
   4. 자동 저장 (수석 검수 통계와 별도)
   5. 변경 감지 → 알림 (예: "베이 028 새로 추가됨")

✅ 데이터 구조 (Firebase):
   ships/{IMO}/  (예: ships/9388417/)
     ├ name: "ATLANTIC PIONEER"
     ├ structure: { bays, pairs, singles, slots, total_slots }
     ├ voyages: { "2622E": {...}, "2624E": {...} } (분석 이력)
     ├ stats: { total_discharge, total_loading, total_voyages }
     └ last_updated: timestamp

✅ 수석 대시보드에 "선박 라이브러리" 섹션 추가
   - 학습된 선박 목록
   - 베이 수, 짝꿍 쌍 수, 단독 베이 수
   - 분석된 항차 누계
   - 양하/선적 누적 카운트
   - 짝꿍 베이 상세 (펼침)

✅ IMO 식별:
   - TDT+20+VOY+++CARRIER+++IMO:146:11:VESSEL_NAME
   - 예: 9388417:146:11:ATLANTIC PIONEER → IMO=9388417, 이름=ATLANTIC PIONEER
   - 7자리 숫자 (ISO 표준, 전 세계 유일)
   - 선박명 변경되어도 IMO는 영구 동일

【테스트】
1. 새 항차 EDI 업로드 → "🆕 새 선박" 알림
2. 같은 선박 새 항차 EDI 업로드 → "📚 학습된 선박" 알림
3. 수석 대시보드 → "선박 라이브러리" 섹션 확인

【다음 항차에서 활용】
- 트윈 짝꿍이 더 정확 (학습된 베이 페어링 활용)
- AI에게 "이 선박 평소 양하 대수는?" 같은 질문 가능
- 통계 누적 → 선박별 운영 패턴 파악
