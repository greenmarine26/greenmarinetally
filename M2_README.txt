  M2.1 — F/E 매핑 정정 (★대형 버그 수정★)
==================================================

★★★ 결정적 발견 ★★★
EDI BAPLIE EQD 끝자리(status)가 그동안 정반대로 매핑됨
  - 5 = Full (Loaded)   ← 그동안 'E'로 잘못 인식
  - 4 = Empty           ← 그동안 'F'로 잘못 인식

이번 ATPR 2622E EDI 검증:
  - status=5: 248개 → 모두 Full (8~28톤 무게)
  - status=4: 20개 → 모두 Empty (3.8톤 컨 자체 무게)

이전 M버전들에서 모든 EDI의 F/E가 통째로 뒤바뀌어 있었음
↓
M2.1: 정정 (5=Full, 4=Empty)

【영향】
- 모든 항차의 F/E 카운트가 갑자기 정확해짐
- 리퍼 온도가 이제 제대로 표시됨 (Full 컨에 온도)
- 통계 답변이 정확해짐 ("풀 몇 개" "엠티 몇 개")
- 카드의 색깔 띠도 정확해짐

【EDI 검증 데이터】
ATPR 2622E (268대):
  - 5 status: 248대 (Full)
  - 4 status: 20대 (Empty - 모두 42PC FR)
  - TMP 세그먼트: 51개 (모두 리퍼)

  M2.2 — 무게/세부정보 사라짐 버그 수정

✅ 문제: 카드/모달에서 무게가 비어 보임 (다른 정보도 일부)

✅ 원인: EDI와 양하리스트(records) 병합 시
        records의 빈 값(0, '', null)이 EDI 데이터를 덮어씌움
        예: EDI wt=28900 → records wt=0 → 화면 wt=0 (빈 값)

✅ 해결: records의 의미있는 값만 채택
        빈 값(0/''/null/undefined)은 EDI 데이터 보존

【영향】
- 카드/모달에 무게 정상 표시
- AI가 무게 정보 활용 가능 ("평균 무게는?", "가장 무거운 컨")
- 다른 정보들도 EDI 값 보존됨 (POL/POD/온도 등)

==================================================
  M2.3 — 리퍼 온도 표시 보강
==================================================

✅ 문제: M2.1에서 F/E 매핑 고쳤지만 옛 데이터엔 적용 안 됨
        → 이미 Firebase에 저장된 fe='E' 그대로
        → 리퍼 + 온도 + Full 조건에서 Full이 안 잡혀 온도 표시 X

✅ 해결: 화면 표시 조건 단순화
        리퍼 + 온도 있으면 무조건 표시 (F/E 무관)
        근거: Empty + 온도는 현장에 없음
              온도가 입력되어 있다는 자체가 Full의 증거

【영향】
- 옛 항차 데이터도 온도 표시됨 (재업로드 불필요)
- 리퍼 카운트 정확 ("리퍼 몇 개" → 온도 있는 모든 리퍼)
- Empty + 온도 같은 데이터 오류도 일단 표시 (검수원이 보고 판단)

【여전히 옛 데이터 → F/E 정확히 보고 싶으면】
자료 탭 → 같은 EDI 재업로드 (1분)
M2.1+로 파싱되어 Firebase 덮어씀
