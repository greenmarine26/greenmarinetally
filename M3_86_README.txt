- src/utils.js의 parseListExcel 재작성

[수정 1] 헤더 정규화에 점(.) 제거 추가
  - 기존: "Cntr.No" 헤더 인식 실패 → fallback 분기 진입
  - fallback에서 4자리 숫자(무게값 "3800"/"2660" 등)가 ISO로 잘못 매칭
  - 결과: ISO 자리에 무게값이 들어가는 사고 (인계서 보고 버그의 진짜 정체)
  - 수정: normHeader 헬퍼 통일 - 점/콤마/괄호 제거, 슬래시 유지

[수정 2] fallback 분기에서 4자리 숫자 ISO 매칭 제거
  - /^\d{4}$/ 패턴 → 표준 ISO 형식만 (/^L\d[A-Z]\d$/ 추가)
  - 안전망: 헤더 검출이 또 실패해도 무게값이 ISO로 새지 않음

[수정 3] type_i 패턴에 "Tp/Sz" 추가 (CDL 양식)
  - CDL 양식의 "Tp/Sz" 컬럼 인식
  - "DC43", "RF40" 같은 합쳐진 표기 자동 분해

[수정 4] fe_i에서 L/S 패턴 분리 + ls_i 별도 추출
  - L/S는 Local/SOC 구분 (F/E와 무관)
  - 기존: L/S 컬럼이 F/E보다 먼저 매칭되어 잘못된 fe 추출
  - 수정: F/E 명시 컬럼만 fe_i, L/S는 ls_i에 별도

[수정 5] ISO 합성 함수 (deriveIso/composeIso)
  - 평택항 표준 (메모리 #15) 기반:
    22G1=20DC, 42G1=40DC, 45G1=40HC, L5G1=45HC, 22R1=20RF, 45R1=40RF
  - 입력 케이스 모두 처리:
    a) 표준 ISO 그대로 ("42HQ", "22G1")
    b) 합쳐진 표기 ("DC43" → 45G1)
    c) Size+Type 분리 컬럼 ("4H" + "RF" → 45R1)

[수정 6] SOC 양식 자동 감지 + Seal 유무 fallback
  - 시트 R0~R5 메타에 "SOC" 키워드 있으면 SOC 양식
  - F/E 미명시 + SOC면 Seal 있음=풀, 없음=엠티
