■ M3.1 핵심 변경 (이번 버전)
───────────────────────────────────────────────────────────────────

[문제 인식]
  EDI 원본 좌표는 BBBRRTT 7자리(예: 0160186)지만
  검수원이 보는 표시는 ##-##-## 형식(예: 16-01-86)이어야 함.
  M2.x까지는 데이터에 앞 0이 그대로 들어 있어 카드/모달에
  "016-01-86" 또는 "0160186"으로 표시되고 있었음.
  업데이트 때마다 이 부분이 자꾸 어긋나서 검수원이 혼란.

[해결 — 데이터 정규화 + 안전망 + 음성 자동화]

  ✅ utils.js: normalizeBay() 헬퍼 추가
     "016" → "16", "001" → "1", "100" → "100" (3자리 베이는 보존)

  ✅ utils.js EDI/ASC 파싱부에서 bay를 정규화해서 저장
     이제 cur.bay = "16" (이전: "016")
     row/tier는 원본 2자리 유지 (이미 ##-## 형식)

  ✅ utils.js fmtPos() 정규화
     이전 데이터(앞 0 있는 형태)도 자동으로 정규화 표시
     → "016" 데이터가 들어와도 "16-01-86"으로 출력

  ✅ BayPlan.jsx: 그룹화 키도 정규화 (이전 데이터 호환 안전망)
     혼합 형식("016"+"16")이 와도 같은 베이로 묶임

  ✅ BayPlan.jsx: 페어링 로직을 정수 기반으로 변경
     padStart 의존성 제거 → 어떤 베이 길이가 와도 안전
     화면 표시는 항상 보기 좋게 2자리(베이 100+는 3자리)

  ✅ utils.js spellPos() / spellPosString() 음성 헬퍼 추가
     "16-01-86" → "십육번 베이 공일에 팔육"
     "1-04-82"  → "일번 베이 공사에 팔이"
     "100-02-88" → "백번 베이 공이에 팔팔"
     베이는 한국어 정수, row/tier는 자릿수별 발음

  ✅ voice.js speak(): 음성 합성 직전 좌표 패턴 자동 변환
     AI 답변에 "16-01-86"이 있으면 자동으로 "십육번 베이 공일에 팔육"
     으로 변환되어 검수원이 한 번에 알아들음
     (화면 표시는 그대로 "16-01-86")

  ✅ voice.js speakContainer(): 위치 발음 자연화
     이전: "베이 16, 로우 1, 티어 86"
     이후: "16번 베이, 공일에, 팔육"

  ✅ gemini.js: AI에게 보내는 좌표도 정규화 (compactContainer/buildBayStats/buildDgList)
     AI 답변 규칙에 "위치는 ##-##-## 형식, 베이 앞 0 없는 정수" 명시
     음성 합성기가 자동 한국어 변환한다고 알려줘서 AI가 형식 헷갈리지 않음

■ 데이터 흐름 (M3.1)

  EDI 원본          :  0160186
       ↓ parseBAPLIE (정규화)

       ↓ fmtPos
  화면 표시         :  16-01-86       (검수원 친화)
       ↓ speak()
  음성 합성         :  십육번 베이 공일에 팔육

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  베이그림(BayPlan) :  bayGroups["16"] (정수 키)
                      셀 표시: ....160186 (7자리, V37 호환)
                      페어링: 정수 비교 (16 + 17 짝꿍)

  Firebase 이전 데이터(앞 0 있음)도 자동 호환:
    fmtPos가 정규화 → 표시 OK
    BayPlan 그룹화 키 정규화 → 그림 OK
