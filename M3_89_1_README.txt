M3.89.1 변경 사항 (2026-05-08 새벽 - 베이플랜 진짜 근본 fix)
============================================================

사용자 의견: "EDI 파악할 때 모든 베이를 풀로 채운 것처럼 생각해서
              만들어 달라. 풀로 채우면 전체 외관이 나올 테고
              그 후에 공간을 비운 후 실제 데이터를 넣으면 전체가 보임"

== 이전 fix가 부족했던 이유 ==

M3.89: BayPlan에 모든 EDI 컨 전달 (평택 외도)
  → BUT 페이지 구성 자체는 여전히 "EDI에 있는 베이만"
  → EDI에 없는 빈 베이(1~maxBay 사이)는 페이지에서 빠짐

== 진짜 근본 fix (M3.89.1) ==

페이지 구성 로직:
  - 1번부터 maxBay까지 모든 베이를 무조건 페이지로 추가
  - EDI 데이터가 있는 베이 → 컨테이너 표시
  - EDI 데이터가 없는 빈 베이 → 빈 그리드 표시 (페이지는 존재)

코드 변경 (BayPlan.jsx):
  - hasEven/hasOdd 조건문 모두 제거
  - if (baySet.has(...)) 체크 모두 제거
  - 1~maxBay 모든 짝수 베이는 페어 페이지, 홀수는 단독 페이지
  - 짝꿍이 maxBay 초과면 단독 (예: maxBay=28일 때 28번은 단독 40ft)

빈 베이 표시:
  - 페이지 헤더: "BAY 04 / 05" 정상 표시
  - bayGroups[evenBay] || [] → 빈 배열 → 컨 0대
  - globalRowRange + globalTiers는 페이지 공통 → 빈 그리드 정확히 그려짐
  - 모든 셀 dashed border (빈 슬롯)

== 사용자 원칙 #8 정리 ==

"EDI 파악할 때 모든 베이를 풀로 채운 것처럼 생각"
  = 1번~maxBay 모든 베이를 페이지로 표시
  = EDI에 컨이 있든 없든 그리드는 그려짐
  = 빈 베이도 빈 그리드로 표시 (베이 누락 절대 X)

이게 진짜 "선박 적부도" 표시 원칙.
